# Mac Agent 连接修复与更新

## 更新到 1.0.9

1. 退出正在运行的 StopWatch Codex Agent。
2. 打开新 DMG，用其中的 `StopWatch Codex Agent.app` 替换
   `/Applications/StopWatch Codex Agent.app`，再正常打开应用。
3. 在“诊断 → 版本”确认是 1.0.9。旧进程不会自动加载新二进制。
4. 打开手表的 Codex 页面，在 Mac 的“Agent 设置”中启用手表连接，或点击“立即重新连接”。
5. 首次配对时核对 Mac 和手表上的六位验证码，并在手表上确认。
   已授权的手表沿用原有凭据重新认证。

本轮已获用户明确授权更新 `/Applications/StopWatch Codex Agent.app`、重启并验证 BLE；实际安装、重启和连接结果应在验证记录中分别确认。

不要删除 Keychain 凭据或重置蓝牙权限。语音驱动未安装与 BLE 配对相互独立；
本次连接修复不需要安装 BlackHole、部署语音后端或进行 Wi-Fi 配网。
如果 macOS 在升级后询问访问原有 Keychain 项目，确认应用身份后允许访问，
再查看日志中的后续连接状态。

## 看连接状态与日志

菜单区分初始化、正在扫描、未发现手表、连接中、配对中、等待手表确认和已连接，
并显示蓝牙不可用或连接错误。连接开关来自实际运行状态；禁用后重新连接会重新启用它。
命令队列关闭或繁忙时会显示错误，不再静默忽略操作。

“诊断 → 打开日志”打开：

```text
~/Library/Logs/stopwatch-codex-agent.log
```

日志从正常启动的最早阶段开始追加写入，包括原生 stderr 输出、BLE 初始化、适配器、
扫描、连接与认证错误。打开日志不会创建或清空文件。每次启动时，若日志已达到 8 MiB，
会轮转并最多保留两份历史文件。日志不记录认证密钥、OAuth Token、Cookie 或通信载荷。

菜单语言跟随系统首选语言：简体或繁体中文都显示简体中文，英文显示英文，其他语言
回退英文。修改系统语言后重新打开 Agent。任务原文、用户命名和原始诊断错误保持原样。

## 本轮修复依据

- 原 Agent 仅扫描状态服务 `7a230001-5474-4f50-5741-544348434f44`，
  而现有固件广播语音服务 `7a230005-5474-4f50-5741-544348434f44`。
  新 Agent 不再用错误的服务 UUID 做系统层扫描过滤，在本地按设备名或已知服务筛选，
  发现后仍验证原有 GATT、安全配对、手表身份与加密会话。
- 使用当前应用的标准 `NSUserDefaults` 域，不再把自身 bundle ID 作为 suite 名称。
  同域中的既有连接偏好得以保留。
- 贯通菜单回调、运行态和菜单勾选状态；“立即重新连接”会实际重启连接流程。
- 启动时将日志持久化，不再依赖 Finder 丢弃的 stderr。
- 未显式命名时复用现有默认 Agent 名称，避免首次安全配对因空名称失败。

这部分只更新 Mac Agent，可与当前手表固件配对，无需先刷固件。

## 手表页面更新是另一项操作

固件中的 TRAE 页面已移除。页面顺序为：麦克风 ← Codex → 额度统计 → 主机监控。
此前额度页和主机页初始化时覆盖了轮播坐标，导致左侧出现主机页、右侧出现空白页；
本轮保留轮播容器分配的位置。Codex 主页面继续显示模型、推理强度、任务及提醒。

新的页面布局和环境页图标需要重新刷入固件才会生效。本轮直写已获用户明确授权，无需先备份完整 16 MiB Flash。使用通过容量门禁的候选固件和实际检测到的完整串口路径；保留原分区、NVS、配对凭据和存储，不执行全片擦除。写后核对写入映像哈希，并从串口确认新固件启动。完整 Flash 备份脚本仍可作为可选恢复手段；实际写入、校验、启动和 BLE 结果分别记录。
